# Migration runbook

## Goal

Перевести проекты с разрозненных `.agents/skills`, `.claude/skills` и
`.codex/skills` на один проверенный каталог без резкого переключения.

## Phases

1. **Discover** — проверить `registry.yaml` и `inventory/skills.tsv`.
2. **Review** — просмотреть конфликтующие хэши и внешние ссылки.
3. **Canonicalize** — исправить относительные ссылки, добавить metadata и
   проверки для выбранного навыка.
4. **Project-enable** — подключить один профиль в конкретном репозитории.
5. **Observe** — сравнить ошибки, время работы и пропуски правил.
6. **Clean up** — отдельным изменением удалить подтверждённые legacy-копии.

## Safe project switch

Перед переключением:

- прочитать ближайший `AGENTS.md` проекта;
- проверить `git status --short`;
- сравнить локальные файлы навыков с inventory и не перезаписывать изменения;
- выбрать профиль явно;
- прогнать обычный project quality gate.

Во время rollout старый каталог остаётся fallback. При расхождении правил
приоритет имеет более специфичный `AGENTS.md` проекта, а не центральный
профиль.

## Conflict policy

Разные версии одного id не объединяются автоматически. Они получают namespace
по проекту или продукту. После сравнения поведения можно создать единый skill,
обновить profile и только затем вывести варианты из эксплуатации.

## Rollback

Удалить ссылку на профиль или вернуть старый loader проекта. Не удалять
канонические файлы и не использовать массовые destructive-команды.
